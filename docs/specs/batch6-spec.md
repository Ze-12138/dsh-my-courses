# 批次⑥ 规格：融合开源论文阅读器的阅读体验（待批准）

> 状态：**提案**。用户原话：「可以融合 github 上的论文阅读插件」。
> 参考对象（只借鉴交互与提示词思路，不复制代码）：
> - [`xiayifan1024/dsh-pdf-math-reader`](https://github.com/xiayifan1024/dsh-pdf-math-reader)（MIT，DSH 插件）：本地 pdf.js 渲染 + 段落级双语对照 + 术语表 + 段落笔记/高亮 + 带范围的 AI 阅读 + 导出双语 Markdown。
> - [`PDFMathTranslate`](https://github.com/PDFMathTranslate/PDFMathTranslate)：保留公式/引用语义的学术翻译思路。
> - [`paper-qa`](https://github.com/Future-House/paper-qa)：回答必须带文档出处（citation）的问答范式。
>
> 许可与依赖边界：借鉴的是**做法**，代码由我们在 `my-courses` 内重写；不新增运行时 CDN、不引入 npm 运行时依赖；`pdfjs-dist@3.11.174`（Apache-2.0）仍是我们唯一第三方运行时，继续本地 vendored。

## 一、目标与非目标

**目标**：让批次⑤的文本层工作台具备「读得下去」的四件事——逐段对照、术语一致、可记笔记、回答有出处。

**非目标（本批不做）**：
- 不做 PDF 原页 canvas 渲染/翻页/缩放（那是 ⑥b，见 §九）。
- 不做整篇一次性机翻（成本不可控，也容易出「看起来通顺但错」的译文）。
- 不引入向量库/embedding；检索仍用现有词面检索。

## 二、阅读视图三态（`原文 / 双语 / 仅译文`）

- 阅读器工具栏新增三态切换，状态存 `paper.items[id].view`（`'en'|'bi'|'zh'`，默认 `'bi'`），不写入全局 ui。
- `bi` 的对照粒度 = **段落**，但只在模型按约定格式返回时对齐：
  - 请求：把该节段落编号成 `[1] … [2] …` 发送（沿用 `mode: 'section'`，新增可选 `align: true`）。
  - 返回格式要求：每段一行 `[n] 中文`。
  - 客户端用 `parseAlignedTranslation(text, n)` 解析：段号必须 1..n 连续且齐全。
  - **不满足就不对齐**：退化为整节中文块，并在块首标注「本节未能逐段对齐」——绝不把错位的句子贴到英文段落下面。
- `zh` 隐藏英文正文但保留章节标题与段落锚点；`en` 隐藏中文块，只留原文（性能上等于批次④的行为）。
- 对齐结果缓存进 `sectionsZh[key].aligned`（数组，长度 = 段落数）；整节缓存仍保留，避免重复计费。

## 三、术语表（专业方向一致性）

- 位置：`profile.glossary`，全局（跨论文），每行 `source=target` 或 `source：target`，最多 40 条，单条 ≤64 字符，超限丢弃并在 UI 提示。
- 注入：`/paper/explain`（guide/section/sentence）与 `/paper/ask` 的 system 提示追加「术语表（必须遵守）」段落；宿主校验数组、去重、截断，**不信任客户端**。
- 生效范围只在提示词，不做后处理替换——避免把正文里的普通词误替换。
- UI：工作台右栏折叠区「术语表」可增删；空表时不注入。

## 四、段落笔记与高亮

- 数据：`paper.items[id].notes = [{id, sec, para, quote, text, at}]`，单篇 ≤200 条，`quote` ≤160 字符，`text` ≤2000 字符；存 localStorage（`version: 11` 迁移，纯函数、幂等）。
- 交互：段落悬浮按钮「记笔记」→ 右栏「笔记」页签出现输入卡；保存后：
  - 该段在正文里加 `.mc-wb-has-note` 高亮（左侧色条，不用背景色，暗色下也稳）；
  - 笔记列表按时间倒序，卡片显示 `§标题 ¶n`、原文摘录、笔记正文、编辑/删除；
  - 点卡片滚动到该段并短暂描边（复用现有锚点滚动）。
- 现有「读不懂」段落解读与笔记互不覆盖：解读在段后，笔记只在右栏。

## 五、提问范围与引用

- 提问框上方加范围选择：`本节`（默认，当前滚动位置所在节）/ `全文`；`本节` 时上下文只带该节文本，省 token 也更准。
- 回答必须带出处：提示词要求引用格式 `[§2.1 ¶3]`。
- 客户端 `parseCitations(text)` 把 `[§… ¶n]` 渲染成可点击 chip，点击跳段；解析失败的引用原样显示，不做猜测。
- 无全文/无该节时如实回 `NO_PAPER_TEXT` / `NO_SECTION_TEXT`，不编造。

## 六、导出

- 工作台头部「导出」→ 生成 Markdown（标题、venue/CCF、原文节标题 + 中文对照、笔记列表、引用 URL），用 `Blob` 下载，文件名 `<id>.md`。
- 只导出已有内容，不触发新的模型调用。

## 七、状态、i18n 与门禁

- `normalize` 版本 `10 → 11`：新增 `view`、`notes`、`sectionsZh[].aligned`；迁移纯函数、重复执行字节一致。
- 新 i18n key 约 26 个（`wb.viewEn/viewBi/viewZh`、`wb.glossary*`、`wb.note*`、`wb.scope*`、`wb.export*`、`wb.alignFailed`、`wb.citeJump` 等），中英各一份。
- 门禁新增：
  - `check-client.mjs` V47 三态切换与 `mc-wb-view` 标记、V48 术语表 UI 与注入请求字段、V49 笔记写入/高亮/列表、V50 范围选择与引用 chip、V51 导出函数、V52 CSS（高亮色条用 token）。
  - `check-logic.mjs` block 19：`parseAlignedTranslation`（齐全/缺号/乱序/多段/空）、`parseCitations`（合法/越界/无 §/嵌套）、`normalizeGlossary`（分隔符/去重/上限/空值）、v10→v11 迁移幂等、笔记上限。
  - `check-host.mjs` block 11：`glossary` 非法类型 → 400、超长截断、`align` 参数只影响提示词、`scope=section` 缺节 → `NO_SECTION_TEXT`。
- 渲染探针扩展：三态渲染、笔记保存后高亮、引用 chip 点击跳转、导出按钮存在。

## 八、不可由代理验证

- 模型是否稳定按 `[n] 中文` 返回（对齐失败率只能靠真实调用观察；失败会退化，不会错位）。
- 真实论文的引用是否准确到段（模型可能编造段号；我们只做「可点击」，不做「正确性背书」，UI 上注明）。
- 笔记在长文（>80 段）下的滚动性能。

## 九、⑥b 候选（本批不做，需另开规格）

- 原版 PDF 页面渲染：`pdfjs` 移到浏览器端 + canvas + 文本层选词，做「左原页 / 右译文」的真正双栏，支持框选翻译与区域高亮。体量与风险都显著大于 ⑥a，且需要重新评估 8 MB / 200 页上限与内存。
- 图形公式/表格识别（需要版面模型，超出「纯文本层」边界）。

## 十、取舍

- 对照粒度段落化但**失败即退化**：宁可整节中文，也不做假对齐。
- 术语表只进提示词：不做事后替换，避免误伤。
- 引用只保证可点击，不保证模型段号正确：这是模型能力边界，UI 明示。
- 不引 canvas：本批仍不渲染 PDF 像素，扫描件继续如实报 `PDF_NO_TEXT`。
